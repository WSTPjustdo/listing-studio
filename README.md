## 启动

安装 Node.js 24+，Windows 双击 start-local.cmd；首次联网安装依赖并构建，保持服务窗口运行，访问 http://127.0.0.1:8787/。开发使用 npm ci、npm run dev（页面 5173，API 8787）。生产使用 npm run build、npm start。不要直接双击 index.html。

装依赖要多久（2026-10-30 本机实测，不是估的）：空缓存 `npm ci` **10.7 秒**（下载 46 MB 进 npm 缓存），热缓存 10.6 秒，装完 `node_modules` 225 MB / 269 个包。日志里会出现两条 `tarball data ... seems to be corrupted. Trying again.` 的 warn——那是 npm 缓存的自愈重试，最终 `added 269 packages` 就是装好了。换网络、换机器数字会变。

双击到能打开网页多久（同日本机实测，`npm run probe:start`，干净导出的 708 个文件、无依赖无产物）：第一次 **11.8–13.1 秒**（含装依赖），同一个窗口关掉后再双击 **2.5–2.7 秒**（不再重装，只重建前端）。**双击两次不会启动第二个**：8787 上已经有一个本程序在跑时，窗口会说「已经有一个 Listing Studio 在运行（版本 x）」并给出地址，退出码按「不算失败」处理；如果 8787 被别的软件占着，它会说明是别的程序并给 `set PORT=8788` 的换法。改之前这里是一段 18 行的 Node 堆栈。

在“模型设置”使用自己的 DeepSeek 或兼容接口配置。默认地址 https://api.deepseek.com，默认模型 deepseek-flash，密钥仅在本机填写；也可复制 .env.example 后私下配置。页面配置优先于环境配置。本工作台拒绝演示模式的新任务，不提供模拟返回替代。模型调用按服务商实际用量计费。

## 导入后二次加工

在“更多功能”选择“导入已有文案”，或从有提示词路径点击“直接检查文案”：粘贴或读取UTF-8 TXT（最多100KB）→选择“我的初稿”或“竞品参考”→识别并核对分段→可选填写关键词与来源→明确确认美国站棉布袋范围后提交。我的初稿可不关联商品，但不执行商品档案核对；竞品参考须选择真实自家商品，生成后独立审核。未知站点/品类可先整理输入，暂不提交此范围的审核。CSV/XLSX插件列结构尚未适配。

每版保留原始材料和词表快照，显示词条前后出现变化；词出现不代表事实成立或搜索量。对话修改可定位到某条五点，其他字段由服务端保留；修改后真实复检并另存版本。JSON/TXT/HTML/工作单附来源和词条说明，纯英文复制不带内部说明。

工程检查：npm run test:intake。新增真实验收需先准备隔离工作区并启动真实服务，见[步骤](reports/secondary-processing-2026-10-30/README.md)；npm run test:live:intake / npm run test:live:intake:browser 会调用付费模型。

## 两条业务流程

1. 新品：录入 / 导入真实商品 → 确认事实与来源 → 选择目标买家、场景、购买顾虑和风格 → 生成英文 → 独立调用审核 → 修改与复检 → 固定版本并导出。
2. 存量文案：关联真实商品与已有英文 → 诊断规则和证据问题 → 修复文字或交接补资料 → 采用最新资料真实复检 → 保留原版本、差异与未解决问题。

对话修改可选择整份文案、只改标题、只改亮点或只改描述。指定范围外字段由服务端保留原文，然后审核最终文案。表达方向不是商品事实，不能用“企业定制”选项证明印刷或定制能力。

“编辑资料”支持为参数关联来源链接、发布方、适用型号与摘录，并添加完整英寸尺寸、拉链、口袋等原文事实。参数变化后解除旧来源，未知材质可留空；再次导入 Amazon 页面保留商家确认资料。资料清单只表示填写情况，不等于核验通过。

修改指令支持多行、完整预览及 Ctrl/⌘+Enter 提交。英文模板追加到现有要求，资料不足时允许少于五条要点；缩短标题保留要点中的完整尺寸。同一参数的重复发现分组展示，展开仍可逐处处理。该次改进结果与模型失败记录见 [2026-10-24 商家反馈改进验收](reports/merchant-improvements-2026-10-24/README.md)。

## 采购补资料交接

审核页 → 核对 / 补充商品资料 → 导出补资料交接 Excel。采购或供应商填写黄色列中的材料名称、适用型号、出具方与来源原文；负责人 / 截止日期可留空。回传 XLSX 后预览，运营逐项选择并确认接收，再真实复检。

接收只新增商品版本及待核验材料，不修改已确认参数，不自动证明认证或性能。拒绝错商品、改动任务信息、公式、重复材料及过期版本；整次确认原子保存。未填写材料的行跳过。文件最多 5 MB / 200 行；只在原工作台有效。商品、文案或规则更新后重新导出，不直接套用旧表。

## 参数与来源的程序关联

已确认的商品参数按原文片段、字段、单位、商品快照及来源 ID 建立关联，不依赖模型返回 claim_map。支持当前棉布袋常见材质 / 百分比、克重、尺寸、容量、提手长度及已确认零售件数；受控换算 mm / cm / 英寸、ml / L，保留尺寸轴顺序。仅在尺寸原文明确自标约数且发生受控单位转换时，按各轴自身原文精度核对容差；无约数标记或同单位不放宽。其他单位原文仅按已存原文关联，不自行推导等价。

待核验材料、平台规则和监管指引不作为商品参数来源。不同属性不能共用相同数字：容量不证明承重、克重不证明单件重量、装箱数不证明零售件数。否定 / 限定、未识别数值和不一致项保留待核对。页面及 JSON / TXT / HTML / 台账 Excel 保留关联依据。

这项程序仅核对可识别的参数，不能证明整句、性能、认证或实际库存。语义和条件继续由真实模型与对应规则审阅。不能把相同参数对应来源当成整句全部成立。详见 [本轮参数验收](reports/parameter-links-2026-10-23/README.md)。

## 审核与版本

可先“不关联，仅检查文本”，再选择真实商品“关联这份资料并复检”，以新版本保存，正文保持原样。未关联时资料检查没有执行；规则、商品资料、识别算法或范围变化后，趋势不直接把问题减少称为改善。

每个发现可展开依据，官方文件与项目内部约定分开，亮点字段例外保留。报告采用当时规则和来源快照，未知历史依据不套当前规则。支持查看/打印 HTML 完整报告及单独改稿工作单，页数随内容变化。

参数识别支持明确 wide/high/deep 轴名、受控单位和可选深度，材质区分成分比例、里料和辅料。轴、单位或资料不明时保留待核对；当前算法 v2.4 进入一致性指纹。参数核对范围显示未覆盖项，参数已关联不证明整句成立。

硬规则、商品参数对照和真实模型审阅共同工作。相同正文、商品资料、规则、来源及模型配置的复检若出现不同结论，会显示一致性提醒并保留为待人工核对。首次运行仅建立基线；这项检测不保证消除误报或漏报。

每版保留商品快照、规则版本、来源、实际模型请求 ID、用量和运行记录。“未发现问题”仅表示已执行检查范围内的结果；缺资料、未检查和执行失败均保留。

## 商品台账、批量与研究

- Listing 台账：搜索商品 / SKU / ASIN，固定真实文案版本，导出英文及审核来源两个工作表。已上架仅商家手动登记，不连接 Seller Central。
- 批量商品：XLSX / UTF-8 CSV / 制表符 TSV、TXT，最多 2000 行、1000 列、5 MB；自动选择商品工作表和表头，可手动切换工作表、指定表头行；支持五点分列和单列换行两种映射。真实 SKU 缺失、重复或变更时阻止处理，不自动生成货号。
- 图片与竞品研究：文字、自己商品链接与可选视觉输入；搜索候选后由商家选竞品、选词。竞品参数不是自己商品证据，词条频次不是搜索量。视觉模型尚未真实验收。
- 本地 Amazon 检索额外需要 Python，先执行 setup-amazon.cmd。也可配置自备第三方商品 API。公开抓取可能失败，未保证持续可用；开源代码许可不代表数据使用授权。

批量任务从商家正在使用的库存文件开始：确认工作表、机器字段表头及 SKU 映射，核对五点列和父子关系，再检查导入内容并启动真实模型。父体行保留，不调用模型；子体按自己的资料处理。SKU 和变体关系需在原文件确认后重新导入，不能靠工作台中的临时修改替代原文件。界面已提供四站点棉布手提袋的语言选项；本轮只核对批量页面入口，未执行真实商家表格批次，不推测其他类目的字段规则。

批次完成后先“检查回填条件”，再“回填并导出库存模板”。工作台按原 SKU 和原行回填已保存的真实审阅文案；XLSX 保留原工作簿中的工作表与未修改单元格，TSV/TXT 只输出所选数据工作表。导出文件版本及行号映射保存在本机。商家上传自己的 Amazon 处理报告时，选择报告对应的导出文件版本，并确认记录号是否包含表头；含糊或冲突的匹配保持未关联。手动修正不会自动标为已解决，涉及文案的未复检修改须通过“错误行修正稿（未复检）”交付，不能冒充已经复检的文案。库存模板版本兼容、平台接收及上架结果均需另行核验。

## 真实验收

下面的命令分成三组：**不需要任何前置**的、**只读本机已有真实记录**的、**会调用付费模型**的。分组不是按名字猜的——2026-10-30 在一台没有 Key、数据库里没有真实文案的机器上逐条跑过，跑不动的那些现在会明确退出并说明缺什么，不再甩一句 `assert.ok(record)`。一条命令可复核这张清单：`npm run audit:delivery`（加 `--run` 会真的执行不需要 Key 的那几条）。

不需要 Key、不需要网络、也不要本机记录的（实测全部通过，单条 0.5–1.6 秒）：

- npm run test:integration：31 项融合工程检查，不调用模型，不替代真实验收。
- npm run test:merchant-facts：商家事实、来源保留与改值解绑的程序检查，不调用模型。
- npm run test:flat-file：文件结构、转义、回填及报告关联的程序边界检查；结构 fixture 不是商家商品、官方库存模板或真实平台处理报告，不作为真实验收依据。
- npm run rules:doc / npm run rules:check：生成和核对说明，不代表官方来源重新核验。

只读本机已有真实文案、不生成也不模拟的（数据库里没有对应记录时会退出码 2 并说明缺哪一条）：

- npm run test:parameters：真实商品快照上的程序边界检查，需要一条真实 W101 记录。
- npm run test:live:library：打开真实工作台点一遍台账并导出，不额外调用模型；需要先 `npm start`，且台账里有一条带真实模型调用的 W201 记录。
- npm run test:live:flat-file：实时 Westford Mill 官方 W101 页面、已有真实 DeepSeek 文案、五点映射及缺真实 SKU 拦截；不额外调用模型，不使用厂家产品代码冒充卖家 SKU。需要一条真实 W101 记录，并会联网取官方页面。
- npm run test:live:flat-file:browser：在真实工作台中检查公开来源派生 TSV/TXT 的导入、五点识别与缺 SKU 拦截；需要先 `npm start`。不启动批量任务，不代表商家模板或平台上传验收。

会调用付费模型的（人工在配好 Key 后跑）：

- npm run test:live:integration：已有真实 W101 文案及实时官方来源，真实验证不关联诊断和补关联；默认写入 .runtime/live-integration。
- npm run test:live:integration:followup：在上述同源记录上真实复检、另存版本并导出。
- npm run test:live：实时官方商品、真实生成 / 修复 / 补规格复检。
- npm run test:live:browser：工作台运行后真实复检和浏览器检查。
- npm run test:live:guided：启动隔离工作台后，真实验证两条引导路径的API。
- npm run test:live:guided:browser：真实点击两条引导路径；需先执行 node scripts/validate-live-intake.mjs --prepare，并使用其隔离数据库启动8788服务，详见本轮验收报告。
- npm run test:live:evidence：已有真实 W101 文案、实时官方原文和一次付费复检。
- npm run test:live:handoff：公开官方原文、交接表浏览器回传、相同输入两次真实复检及两轮对话修改。
- npm run test:live:parameters：官方实时资料、两次真实复检、参数关联一致性及浏览器 / 导出验证。
