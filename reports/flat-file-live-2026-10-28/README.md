# 库存文件改进与验收边界

日期：2026-10-28，Asia/Shanghai。本轮根据真实商家关于 Excel Flat File 和 TSV/TXT 的工作方式改进批量工作台。以下“已实现”描述工程能力，不表示已完成商家原件、Amazon 模板兼容或平台上传验收。当前范围仍为 Amazon 美国站、棉布手提袋、英文文案、本机工作空间。

## 七项改动与使用方式

| 商家工作中的问题 | 本轮实现与操作 | 验收边界 |
|---|---|---|
| 库存工作簿可能含说明页、多个工作表和多行表头 | 自动跳过说明 / 定义等辅助工作表，优先寻找商品模板；前 50 行识别字段表头。上传后可以切换工作表、指定表头行并核对预览 | 可识别常见字段结构；没有商家原件，不能声称覆盖全部模板版本 |
| TSV/TXT 还需在外部转换 | 支持 XLSX、严格 UTF-8 CSV、制表符 TSV/TXT；文本保留货号前导零，处理带引号的分隔符、换行和双引号。上限 5 MB、2000 行商品、1000 列，单元格 10000 字符 | 非 UTF-8 文本需先另存；数据区公式需转为值；转文本只输出选定数据工作表 |
| 五点分列与单列换行无法直接对应 | 映射 bullet_point1 至 bullet_point5，或使用一列按换行拆分；不能同时使用两种映射。回填时写回对应的原列，不将全部五点强塞进一列 | 已存真实文案用于映射核对；字段容量不足或映射冲突须先处理，不截断内容冒充成功 |
| 缺货号或重复货号时会生成无业务依据的标识 | 使用原文件中的真实卖家 SKU，检查缺失、重复及不一致；不再自动生成 ROW 货号。SKU 和变体身份须在原文件确认后重新上传 | W101 是厂家产品代码，未确认为任何商家的卖家 SKU；当前卖家 SKU 保持未知，缺 SKU 拦截是预期结果 |
| 父体与子体被当作无关联的普通行 | 映射父 SKU、parent/child、关系类型、变体主题、颜色及尺码；核对关系后保留父体，不为父体调用模型；子体使用自己的资料 | 保留原结构不等于平台认可变体关系；未取得商家的真实变体文件，不能宣称变体上传成功 |
| 导出自定义台账后还要人工搬回库存模板 | 在批次中先检查回填条件，再按原 SKU / 原行回填已保存的真实审阅文案。XLSX 保留原工作表和未修改单元格，可选择输出 TSV/TXT；台账 Excel 仍用于文案管理 | 保留文件结构不证明满足特定站点、类目或模板版本的必填与枚举规则；尚无商家原件往返验收 |
| 平台错误报告和本地改稿无法闭环 | 商家导入自己的真实处理报告，选择报告对应的原始文件或已导出版本，并选择记录号语义。导出版本保存行号映射，SKU / 行号冲突和歧义保持未关联；可保存单元格修正并导出“错误行修正稿（未复检）” | 手动改值不等于模型复检、错误解决或平台通过。没有真实 Seller Central 报告，报告关联和修正稿仅完成工程实现与程序边界检查 |

完整流程为：上传商家原文件 → 核对工作表、表头及映射 → 选择商品并检查内容 → 启动真实模型 → 检查回填条件 → 导出原表副本 → 商家在 Amazon 提交 → 选择所提交文件的导出版本并回传平台报告 → 核对错误关联并修正 → 以未复检修正稿重新提交，或重新导入真实修改文件完成模型复检。工作台未连接 Seller Central，不替商家提交，也不自动核验已上架。
