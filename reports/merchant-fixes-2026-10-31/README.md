# 卖家 P1 问题修复与验收

日期：2026-10-31（Asia/Shanghai）

本次完成卖家报告优先级最高的三项问题，并补上商品参数编辑的关闭保护。

引导流程按“改进提示词 / 自动完成”分别将未完成内容保存在当前浏览器的 IndexedDB。文字、站点与语言、所选商品、步骤、确认字段、研究选择、来源文件和图片可在离开页面后恢复。草稿不会发送到服务端；已完成的结果仍保存在服务端任务记录。恢复提示提供清除入口。

商品资料编辑期间，Escape、关闭弹窗和“返回文案”均不能直接丢弃字段修改；先保存或取消后才能退出。A/B 三版结果按文案任务和基准版本写入本机数据库，关闭后重开直接恢复。每次明确点“重新生成三版”才再次请求模型。选中某一角度后，“采用为新版并复检”通过现有独立审核链路保存下一版本，并记下采用的 A/B 结果和角度。新版本保留真实审核结论，未通过或仍有待核对项时不会标成已通过。

台账主键改为商品与站点组合。SKU、ASIN、管理状态、固定文案版本和导出选择都按站点隔离；Amazon 链接使用对应站点域名。旧台账迁移时优先从固定文案取得原站点，无可用文案记录的旧行归入美国站。过期判断使用该记录所属站点的规则包，不再拿德国或英国记录与美国规则比较。

验证结果：`npm run build` 通过，Vite 仍提示主 bundle 超过 500 KB。聚焦检查 `node --test tests/library-multisite.test.mjs tests/variant-persistence.test.mjs` 通过。`npm run test:live` 使用实时读取的 Westford Mill W101 官方资料及本机 DeepSeek，生成、修复与补规格复检均完成；三次 `MODEL_INVALID_JSON` 的首轮响应均保留，并由原工作流重试成功。`npm run test:live:browser` 最终通过草稿跨导航恢复、真实文案复检、A/B 结果关闭重开、采用与独立复检。`npm run test:live:library` 用已有真实文案完成逐站点固定、刷新保留、手动上架确认校验和 Excel 下载，没有调用模型。

验收脚本初次遇到两处脚本问题，已保留原因并修正后重跑：台账脚本仍寻找已经合并进“我的结果”的旧入口；扩展后的草稿检查把带换行的站点标签按单行精确比较。两次均未触发模型请求。首次台账 live browser 遇到旧按钮定位超时，修正后成功。

本轮共 14 次真实 DeepSeek HTTP 模型响应，合计 93,415 tokens；3 次格式失败均为 `MODEL_INVALID_JSON`，其后工作流重试成功。没有取得账单金额，不从 token 推算费用。请求 ID、模型、耗时、用量与失败码见 [model-call-ledger.json](model-call-ledger.json)。台账 live 验收明细见 [`reports/listing-library-2026-10-23/acceptance.json`](../listing-library-2026-10-23/acceptance.json)；浏览器的脱敏验收报告和截图留在 `.runtime`，不进入分享包。

未解决项：真实审核仍发现 DALIX 文案使用 `22 x 16 x 6` 三轴尺寸，而关联资料只确认宽、高，没有深度；颜色和零售包装件数也保持未知。A/B 采用版本仍有 4 项尺寸依据问题和 2 项缺失资料，不能当作已审核通过的上架文案。没有商家库存表、商家私有 SKU、真实已上架状态或 Seller Central 连接；这些业务效果未验收，也未补造状态。
