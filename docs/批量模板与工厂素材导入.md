# 批量模板与工厂素材导入

2026-10-31。首页可以直接进入「批量导入模板」，两条商品引导路径都可以上传工厂材料。

## 已有亚马逊库存模板

1. 首页点击「批量导入模板」，上传 Excel `.xlsx` 或制表符 `.tsv` / `.txt`，也支持 CSV。
2. 核对商品工作表、表头行与字段映射。支持经典三行表头、新版属性路径、分列五点、父子 SKU 与变体字段。
3. 同名字段涉及多个站点或语言时，需要手动选列；不会自动把另一站点的内容当成本次输入。
4. 逐行核对商品资料和站点/语言，确认模型调用后批量处理。SKU 缺失时保留缺失，不生成虚构卖家货号。
5. 核对处理结果后回填原模板，保留原列、SKU、父子关系及来源行；提交平台后可导入真实处理报告。

文字表支持 UTF-8、带 BOM 的 UTF-16 LE/BE。原格式导出保留 UTF-16 编码及 BOM；明确选择 TSV 转换导出时改为 UTF-8，并提示编码变化。旧版 `.xls` 和带宏 `.xlsm` 请先另存为 `.xlsx`。

这项能力负责模板读取与回填，不能保证覆盖亚马逊全部站点、品类和版本。仍需商家真实下载的库存模板及平台处理报告验收；工作台未连接 Seller Central。

## 工厂直接发来的零散材料

1. 进入「改进我的提示词」或「从商品资料开始」，在工厂资料区域选择多个文件，也可拖放或粘贴剪贴板截图。
2. 点击「提取资料内容」。支持中文 Word `.docx`、PDF、Excel `.xlsx`、CSV、TSV、TXT、PNG、JPEG 和 WebP。
3. 逐份查看原文及位置：PDF 页码、Word 段落、Excel 工作表与行、文本行或分隔表记录。失败文件保留原因，不会冒充识别成功。
4. 选择本次采用的文件，核对和更正文字。确认所选材料属于同一商品，再点击「使用这些资料」。不同商品需分别整理，多个 SKU 用批量模板入口。
5. 继续交给本机已配置的真实 DeepSeek 整理，随后在确认页核对名称、材质、尺寸、容量等参数，再生成文案并独立审核。

上传后的原文件仅保存在本机私有数据库。预览不创建商品；最终商品、模型结果和版本保留文件 SHA256、原始提取内容、采用文件与商家更正。报告导出保留文件和来源位置；纯文案导出不夹带内部材料记录。

## 识别范围

- 每组最多 12 个文件，单文件不超过 5 MB，总计 20 MB；本次采用文字不超过 60,000 字符。
- PDF 最多 30 页。优先提取文字层；无可用文字的页面在本机渲染后 OCR。
- 图片和扫描页使用本机中英文 OCR。识别语言包随 `npm ci` 安装，无需配置视觉 API；数字、单位、中文仍须对照原图。
- 图片只提取可见文字，不从实拍外观猜材质、承重、尺寸或认证。没有文字的照片会提示补充说明。
- Word 嵌入图片需另外上传；`.doc` / `.xls` 请先另存为 `.docx` / `.xlsx`。加密或损坏文件保留失败原因。
- 表格公式及错误值不作为商品事实；隐藏工作表不自动采用。较大材料请按商品拆分。
- 模型结果需人工确认，来源冲突、未知货号、零售包装、性能和认证不得自动补全。

## 开发验收

`npm run test:materials` 为解析与身份保留的工程检查，不能代替真实模型或商家验收。

真实公开资料专项：先启动使用本机已有 DeepSeek 配置的工作台，再执行 `npm run test:live:materials -- --base-url http://127.0.0.1:3221`。可加 `--complete-workflow` 验证提取、确认、方案、生成、独立审核及导出；需要新增真实付费调用。报告可通过 `--resume <acceptance.json>` 续跑既有提取记录。

浏览器专项：`node scripts/validate-materials-browser.mjs --base-url http://127.0.0.1:3221 --real-api`，默认读取上一项在 `.runtime/materials-acceptance/live-materials` 的真实官方资料；也可用 `--source-dir` 指定该专项输出目录。使用真实页面和接口，不拦截模型返回。

标准验收仍为 `npm run test:live` 与启动真实工作台后的 `npm run test:live:browser`。本轮事实、失败和未取得的商家原件见 [验收报告](../reports/materials-intake-2026-10-31/README.md)。
